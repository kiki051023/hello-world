# 职业技术学院学生综合管理平台设计规格

## 目标

在现有 Spring Boot + Vue 3 学生管理系统基础上，平滑升级为面向职业技术学院的综合学生管理平台，保留现有数据，分阶段增加教务、学生事务、实习就业、统计决策和运维能力。

## 已确认范围

- 建设路线：分阶段演进；
- 组织结构：学校 → 系部/二级学院 → 专业 → 班级；
- 首期：独立运行，通过 Excel 和标准 API 交换数据；
- 角色：管理员、教务人员、系部负责人、辅导员/班主任、教师、实习指导教师、学生、校领导；
- 数据：保留并兼容现有账号、学生、教师、班级、课程和成绩；
- 质量约束：业务逻辑放在 Service/领域层，Mapper 仅执行明确持久化和查询，禁止全表加载、循环查询和前端单独授权。

## 总体架构

前端继续采用 Vue 3、Vue Router、Pinia、Element Plus 和 Axios；后端继续采用 Spring Boot、Spring Security、MyBatis-Plus、MySQL、Redis 和 EasyExcel。保持 Controller → Service → Mapper 分层，新增 DTO、数据权限、审计、导入任务和文件对象等边界。

Controller 只处理请求、格式校验和响应；Service 负责业务规则、数据范围、事务、状态流转和 DTO 转换；Mapper 负责单次明确的分页、JOIN、聚合和批量持久化。

## 分期范围

### 阶段一：基础平台治理

修复现有 MyBatis 配置和权限边界；增加学校、系部、专业、学年学期、角色权限、数据范围、字典、审计日志；统一 DTO、异常、分页、导入导出和文件处理；兼容既有数据。

### 阶段二：教务与成绩

培养方案、课程学期、授课任务、选课、分项成绩、综合成绩、补考、重修、学分、成绩审核和成绩变更历史。教师只能操作授权教学任务，学生只能访问本人数据。

### 阶段三：学生事务

学生档案、学籍异动、班级和宿舍、辅导员、请假审批、奖助学金、困难生、奖惩、综合评价、联系人和学生预警。

### 阶段四：实习就业

实习计划、企业、岗位、学生分配、指导教师、过程记录、企业评价、实习成绩、就业去向和技能证书。

### 阶段五：统计决策

学生规模、组织分布、学籍异动、成绩、学分、预警、请假、实习、就业和教师教学统计；高频汇总使用聚合 SQL 和短时缓存，大报表异步生成。

### 阶段六：运维与开放接口

备份恢复、导入任务、异常监控、接口审计、限流、数据交换和后续 SSO/外部系统对接适配。

## 数据模型

保留并扩展现有 `sys_user`、`student`、`teacher`、`clazz`、`course`、`score`。新增或规划 `school`、`department`、`major`、`academic_year`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_data_scope`、`student_status_history`、`student_class_history`、`course_term`、`teaching_task`、`course_selection`、`score_detail`、`score_change_log`、`makeup_exam`、`retake_course`、`student_credit`、学生事务、实习就业、审计和文件相关表。

成绩生命周期固定为 `DRAFT`、`SUBMITTED`、`APPROVED`、`REJECTED`、`VOID`，成绩类型固定为 `REGULAR`、`MAKEUP`、`RETAKE`。只有 `APPROVED` 记录占用 `active=1`；草稿和退回记录允许多个版本，但同一提交事务只能产生一个当前版本；作废记录切换为 `active=0`。补考/重修通过 `original_score_id` 关联原成绩，成绩修改产生版本和 `score_change_log`，当前有效记录由 `active=1` 标识。唯一约束为学生、开课学期、成绩类型和有效标志的组合；版本切换必须在同一事务中完成，并使用乐观锁防止并发审核。迁移前先生成旧 `student_id + course_id` 冲突报告，人工或规则映射后才创建新约束，禁止覆盖原始成绩。逻辑删除只允许用于基础资料和可恢复业务记录；成绩、学籍异动、审计日志原则上只作废不删除。敏感数据独立建表，附件保存对象 ID 而非物理路径。

迁移必须版本化、幂等并可重试，采用 expand/contract：预检 → 备份 → 新表创建 → 回填 → 关联校验 → 冲突报告 → 试运行 → 双读兼容 → 短暂写入停机 → 切换 → 新接口校验 → 只读回滚窗口 → 关闭旧接口。切换前必须满足行数、校验和、唯一性、权限回归和备份恢复验收；切换后校验失败时执行版本化回滚命令并恢复旧读写路径，回滚窗口结束后保留副本恢复路径。需在副本库演练恢复，记录校验口径、RPO/RTO、密码/编码/时区转换和未知组织数据处理结果；任一步失败不得切换生产。

## 数据权限

- 管理员：全校；
- 教务人员：全校教学数据；
- 系部负责人：所属系部；
- 辅导员：负责班级；
- 任课教师：所授课程和授权教学班；
- 实习指导教师：所指导学生；
- 学生：仅本人；
- 校领导：授权统计数据，默认只读。

权限必须由 Service 根据当前用户生成 `DataScope`，并作为查询条件传入 Mapper。任何 `studentId`、`clazzId`、`departmentId` 等前端参数都不能扩大授权范围。

`DataScope` 固定包含范围类型（`SCHOOL`、`DEPARTMENT`、`CLASS`、`TEACHING_TASK`、`PRACTICE_GROUP`、`SELF`）、范围 ID 集合、字段可见级别和只读/可写标志。多角色范围默认取并集，但字段可见级别取最严格值；空范围一律拒绝。列表、详情、统计、导出、批量写入和删除必须经过同一授权服务，管理员也必须留下审计记录。权限变更通过用户 `permission_version` 增长和 Redis 会话撤销实现立即失效；每次请求校验版本，权限服务或 Redis 不可用时默认拒绝敏感读写请求，不能沿用旧 JWT 权限。

权限采用三层矩阵：功能权限决定能否调用接口，数据范围决定能看到哪些记录，字段权限决定联系方式、困难生、处分、实习附件等敏感字段是否脱敏。校领导默认统计只读，系部负责人和辅导员按组织范围授权，学生默认仅本人。所有这些组合均须有越权集成测试。

## 查询与可靠性约束

- 禁止 `selectList(null)` 作为业务数据加载方式；
- 禁止循环内调用 Mapper；
- 关联数据使用 JOIN、批量 IN 或投影查询；
- 列表分页并限制最大页大小；
- 导出按主键分批或异步；
- 统计使用数据库聚合；
- 高频筛选字段建立索引并使用 Explain 验证；
- 批量导入先做文件内重复、数据库重复和业务校验，再在事务中保存；
- 数据库唯一键异常转换为业务错误；
- 重要修改写入审计日志；
- Redis、数据库和文件存储故障具备明确错误响应和降级策略。
- 普通列表最大页大小为 100，单次同步导出最大 10,000 行，超过阈值转异步任务；关键列表查询预算为固定的主查询加最多 2 次批量补充查询，并用代表性数据量的 Explain/SQL 回归测试验收。
- 批量导入必须有任务幂等键、重复提交结果、错误行持久化、事务隔离级别和并发锁策略；数据库不可用时禁止假降级写入，Redis 仅允许安全旁路读取并防止缓存雪崩，文件上传失败须清理孤儿对象。
- 首期 API 即确定版本号、服务身份/令牌、权限范围、幂等键、限流、重试和交换审计；阶段六只增加外部系统适配。
- 审计事件至少覆盖登录、权限拒绝、成绩变更、学籍异动、资助、处分、导入、导出和文件访问；记录操作者、目标、前后值、请求 ID、结果和脱敏策略，并设置保留期限及只追加存储。
- 统计缓存键必须包含规范化后的 `DataScope`、字段可见级别、权限版本、指标参数和数据版本；缓存结果不得包含超出字段权限的数据。权限变更主动删除用户范围相关缓存，且必须测试不同角色先后请求同一统计参数不会串数据。
- 查询预算不包含权限版本解析和缓存命中，但包含分页 `COUNT`；列表最多 2 条 SQL（数据+计数），详情最多 2 条，统计按接口固定指标 SQL 上限，导出走异步任务且不纳入同步列表预算，所有上限用集成测试验证。
- 阶段一只交付同步导入的幂等键、错误行和任务记录；阶段六增加失败重试、清理、监控和运维界面。

## 交付验收

每个阶段必须同时交付：数据库迁移脚本、后端接口、前端页面、权限矩阵、导入模板、单元/集成测试、API 文档、操作说明和回滚方案。阶段验收以数据不丢失、权限不可越权、查询无 N+1、批量导入可追踪、前端构建通过和核心接口可回归为准。

## 风险与优先级

最高优先级为修复 MyBatis 配置缩进、学生成绩越权访问、导入重复数据异常和默认权限边界；随后再扩展业务表和页面。不得在基础权限和迁移校验未通过前上线新业务模块。
